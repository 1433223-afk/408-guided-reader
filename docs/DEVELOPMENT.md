# 开发入口

## 本地运行

需要 Python 3.11+、Node.js 20+ 和 Chrome 或 Edge。在仓库根目录执行：

~~~powershell
python -m pip install -e .
npm ci
python -m reader_service
~~~

本机服务默认只监听 127.0.0.1:8765。Python 入口和服务在 src/reader_service/；网页在 src/reader_service/static/，运行时依赖仓库根目录的 node_modules。测试分别在 tests/、tests-js/、tests-e2e/。pyproject.toml 和 package.json 是依赖与命令入口。

默认数据放在 Windows 用户的 LOCALAPPDATA/408 Guided Reader；开发时可用 --data-dir 指向独立目录。不要把 PDF、数据库、备份、截图、日志或密钥提交到 Git。模型配置项见 .env.example；正常 Windows 使用通过凭据管理器保存密钥，.env.example 不应填真实值。

## 做改动

- 先看当前代码和用户的实际问题。原 PDF 是阅读与来源依据；OCR、知识点、教学内容和学习记录各有自己的持久化边界。涉及身份、数据迁移、原文锚点、学习状态或模型出站时，把验证放在真正产生副作用的位置。
- 本地小修直接复现、最小修改、定向验证。重大能力或架构选择再调查成熟方案；避免提前做通用框架、过度工程化和没有具体风险的防御性分支。
- 修 bug 必须解决导致它的一类错误：确认根因后检查共享逻辑、调用方和同类真实数据，在共同规则处修复并覆盖代表性边界回归。不能只为用户指出的单个题目、页面或截图打补丁；“最小修改”指最小而完整地消除同类原因，不代表只修一个表象。报告说明检查范围、同类影响和仍未验证的部分。
- 新的交互能力优先做可用的短路径，在真实教材中试用。默认跑相关测试和必要的浏览器 smoke，由人实际验收体验；不因每次小改动自动跑全量套件。测试通过不能替代真实使用，也不能把未跑或失败的检查写成通过。
- 当前只允许 DeepSeek 与智谱两个 Provider；不使用 OpenRouter、GPT 或 Gemini，也不自动回退到未经批准的模型。每次真实调用前核对最终解析出的 provider/model；需要例外先由用户明确批准。
- Git 操作先检查工作区，保留用户现有改动。不要擅自 reset、clean、rebase、强推或改写历史；密钥和用户教材始终留在仓库外。

朋友内测服务端方案尚未实施。若以后继续，先重新确认范围；Windows 本地版不能因此退化，多人数据和密钥必须隔离，并单独验证登录、安全、备份与恢复。

新对话接手一项较大的开发任务时，先读 AGENTS.md、docs/PRODUCT.md 和本文，再按任务查看相关代码。连续的小任务、同一问题的修复与验收沿用当前上下文，不重复做完整冷启动，也不默认翻旧阶段资料。

## 桌面版本发布与 GitHub 同步

用户已授权：每次桌面版更新发布时，都要将该版本对应的主线 `main` 推送到 GitHub，作为发布流程的必要收尾，不必再次询问是否推送。

- 按本次发布范围完成必要验证与验收，将对应源代码、版本号和必要发布文档提交并合入 `main`；先检查工作区，不把无关或尚未确认的改动混入发布提交。
- 桌面版发布成功后，正常推送 `main` 到项目 GitHub 远程，核对远程 `main` 与本地发布提交一致，并在完成报告中给出版本号和提交标识。
- 遇到远程新增提交、冲突、权限或网络问题时，保留现有工作，不强推、不改写历史；能安全解决则继续，否则明确报告“桌面版已发布，GitHub 同步未完成”及原因，不能把推送失败写成完成。

## 本地启动与数据维护

- 浏览器首次进入应使用服务输出的完整 `READY` 地址（含当前启动凭证）。页面会清理地址栏中的凭证，并建立本机会话；匿名裸地址不能创建会话。服务重启后旧会话失效，需要重新使用本次启动地址。不要把完整启动地址保存到日志或发给其他人。
- 普通本地数据默认在 `%LOCALAPPDATA%\408 Guided Reader`；当前 Desktop spike 的默认目录为 `%LOCALAPPDATA%\408GuidedReaderDesktopSpike`。以实际启动参数或桌面设置显示的目录为准，不能用开发书库路径替代安装版目录。
- 手工备份：先完整退出桌面应用或停止 Reader 服务（仅关闭网页不足以停止服务），然后复制整个数据目录到另一个备份目录。至少同时保留 `state.sqlite3` 和 `blobs/`，若存在 SQLite 的 `-wal` / `-shm` 文件也一并保留；只复制数据库不能恢复原 PDF。不要在服务仍写入时直接复制数据库文件。
- 恢复前同样停止服务并另存当前目录；将完整备份恢复到独立目录，先用 `--data-dir` 检查书库、原 PDF、来源位置和学习记录，再用于日常阅读。遇到数据库损坏先保留原目录与备份，不删除数据库以强行启动。密钥在 Windows 凭据管理器中，不包含在书库备份内。
- OCR 在本机进行；使用 AI 功能时，问题、所选教材片段或本节/本章证据以及必要历史对话会发往所选 Provider。Guide/KP/Inline 的生成和审查可能使用不同 Provider；没有密钥时原 PDF 阅读仍可使用。当前没有产品内一键备份/恢复入口，干净 Windows 首装与独立系统用户凭据生命周期仍需发行验收。
