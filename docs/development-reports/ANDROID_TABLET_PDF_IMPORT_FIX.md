# Android Tablet PDF 导入链路修复（2026-10-19）

## 证据与范围

延续 `codex/android-tablet-reader` / `ea1d666` 隔离工作区。主线仍为 `main` / `b718e76`，工作树只有原有未跟踪 `website/`；本轮未修改正式学习库。用户补充的现场情况是约 350 页大 PDF、平板内部存储、夸克浏览器，选择文件后完全没有提示。

本轮开始时旧 8876 服务未运行，没有能够还原该次夸克失败的请求记录。因此**尚未确认真实夸克那一次失败的具体原因**，不能把下面的模拟复现当作现场结论。

先用未修代码在本机真实 WLAN `192.168.43.65:8876` 选择原教材抽取的 805,594 字节、2 页 PDF：POST `/api/books` 携带启动凭证，返回 201，入库后 PDF.js 正常显示。接口是 raw PDF，非 FormData；未发现 localhost 地址错误或普遍缺少鉴权。正常浏览器实际生成正确 Content-Length。

另外实际复现了三类具体问题：有效 PDF 无扩展名且 MIME 为空/通用类型时，原前端零网络请求直接拒绝；选中磁盘 File 后仅修改其 mtime，直接 fetch File 稳定触发 `ERR_UPLOAD_FILE_CHANGED`；移除 `AbortSignal.timeout` 时，旧代码出现请求/打开过程异常。旧界面没有持续上传进度，导入成功后的书库刷新/打开与上传共用捕获，也不利于区分阶段。后端缺少 Content-Length 会按空文件处理，断流则可能无限等待；这些属于已复现的边界，而非已认定的 Android 故障原因。

## 最小完整链路

- `pdf-upload.js` 以 4 MiB 块读取为独立 Blob，使用 XHR 同源上传以提供进度；原请求路径、raw PDF、当前 launch token/cookie 保留。没有把整本文件变成单一大 ArrayBuffer。文件类型最终由 Core 的 PDF 校验决定，空文件与 2 GiB 限制明确提示。
- 书库提供一行持久的读取/上传/验证状态和错误反馈。输入复位、重试可用；上传成功与后续打开失败分开说明，新书直接来自成功返回结果，不等待无关的继续阅读摘要。
- 轻量经典脚本在主模块未启动时提供可见提示；启动前选择文件后，即使主程序迟到，也保留重新选择提示。请求超时使用兼容的 AbortController 回退。
- Core 记录不含凭证、文件名与 PDF 正文的 `PDF_UPLOAD received/result` 日志，响应返回 `X-Reader-Upload-Id`。鉴权仍先于上传 framing 错误；明确 411 缺长度、400 非法长度/中断、501 不支持传输方式、408 接收正文时 90 秒空闲超时。网络读错误不再伪装成存储错误，临时上传清理仍执行。

只跑必要检查，没有全量测试、模型调用或公网发布。

- 31 个上传、存储、原 API 授权和 LAN 必要定向 Python case 通过。
- `tests-e2e/tablet-import.mjs` 使用现有 pypdf 生成 350 页、10,591,258 字节 fixture，在无模型/OCR实例的临时 LAN Core 上运行 Chrome：多块读取、无扩展名/通用 MIME、201 入库并 PDF.js 显示、非法 PDF 422、真实过期凭证 401、主模块失败提示、迟启动重选提示、缺少 AbortSignal.timeout 后重复上传/打开均通过，临时库已清理。
- 当前真实 Demo 的 Chrome/触控视口：原 348 页教材完整 150,123,418 字节重新上传，服务日志与请求头长度一致，返回 200 `PDF_UPLOAD_DUPLICATE`，已有书正常打开。两页真实教材样本 805,594 字节通过固定 UI 返回 201 `PDF_UPLOAD_IMPORTED`，新书出现在隔离书库并打开。只替换本轮自行创建的同名测试样本，没有操作用户书籍。
