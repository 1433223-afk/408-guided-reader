# Android Tablet Directory 布局修复

2026-10-19，独立分支 `codex/android-tablet-reader`，基线 `c4ea106`。本轮仅调整平板目录及它与既有 Assistant 的空间切换；未合入 main、未改 Windows Desktop 或正式书库。

## 问题与处理

原平板目录是宽 376 CSS px 的绝对定位抽屉，并在剩余 PDF 上铺遮罩；800 CSS px 竖屏下目录直接盖住近一半原书。标题 span 仍继承桌面的单行省略与 12.5px 字号，仅放大父按钮没有改善实际文字展示。

参考已验收的桌面竖屏报告，并向用户指定的「桌面版开发」对话核对布局、顶部阅读锚点和会话保留原则后，采用以下安排：

- 横屏且宽度至少 960 CSS px 时，目录占独立左栏，宽度随可用空间约束在 304–344 CSS px。
- 竖屏或窄窗口中，目录进入 PDF 下方的独立工作区，约占窗口高度 40%、最高 460 CSS px；不设强制大最小高度。PDF 保持全宽，目录标题固定、树单独滚动。
- 移除遮罩。真实标题完整换行，字号 15px，层级靠缩进、颜色和字重；保留至少 48px 的触控目标。
- 目录与 AI 互斥展示。打开目录时收起 AI 和输入焦点，保留会话与草稿；关闭目录恢复此前的 AI。顶部「继续解释」可直接切回 AI。
- 点目录目标时先完成关闭后的布局，再应用原书定位。开合与旋转保存顶部原书锚点及缩放；晚到的 resize 不恢复旧目标。宽度变化仍调用现有 PDF 重排，文字、画布和来源坐标共用原规则。

全部样式与接线以显式 tablet 模式为边界，没有改 OCR、PDF 上传、PDF Range 策略、数据库或模型调用。

## 验证

使用临时书库快照，在真实私网 IPv4 HTTP 上打开 348 页组成原理 PDF，复用已缓存 OCR 和目录；不发起新 OCR 或模型请求。浏览器为桌面 Chrome 的触控 viewport，不能替代 Y900 原生浏览器结果。

- `tablet-directory.mjs` 覆盖 1200×800、800×1200、900×600、800×520、600×900 CSS viewport：独立空间、不遮 PDF、底部工作区保留至少一半可用阅读高度、长标题换行、48px 点击区、独立目录滚动、折叠不移动原书、125% 缩放下开合和旋转锚点、稳定目录跳转，以及 AI 选文草稿恢复。另检查不带 tablet 参数的桌面目录及原竖屏菜单。
- `tablet-pen.mjs` 的真实教材选字与跳转回归通过，包括正反笔拖动、笔后手指滚动、目录跳转、第 348 页显示及 Range 字节长度。CDP 笔事件不代表联想主动笔真机验收。
- Directory / reading-display 共 10 项 JS 定向检查通过，修改模块语法与 diff 空白检查通过。未跑全量测试。
- 当前 `192.168.43.65:8876` Demo 已确认返回更新后的目录 CSS、布局模块和页面，无需重启或变更访问凭证。

早期截图出现“学习服务不可用”，原因是缓存测试 Core 未提供已有学习记录的 GET 服务；补齐测试 fixture 的只读 repository 访问后消失，生产代码未因此修改。最终交付截图另在 100% 倍率拍摄，并等待提示自然消退。

截图保留在 ignored `test-results/tablet-directory/`，已逐张检查横竖屏目录和 AI 空间。主线 HEAD 仍为 `b718e767f67406c3e4241d78a5adbead5b9d94bb`，原有未跟踪 `website/` 保留。

## 人工验收

在 Y900 Chrome 刷新当前 Demo，分别横竖屏打开目录、展开长标题并滚动目录树，确认上方/右方原书不跟随滚动；跳转、关闭和旋转后核对原书位置。已有 AI 对话时切换目录再返回，检查对话与输入草稿仍在。

真实 Android 系统栏、输入法收起时机与触控手感留待用户人工验收；本轮不增加面板拖拽高度、全屏目录或新的学习功能。连接方式见 `docs/ANDROID_TABLET_DEMO.md`，服务保持运行，停止扩展并交回验收。
