# Reader 首屏显示优化

2026-10-22。用户反馈 Desktop 0.4.12 启动后第一次打开已有 PDF 仍有明显等待，并要求以“点开就能阅读”为目标继续优化。

## 调查结论

之前的通用性能优化主要消除了资源累积与重复查询，并没有单独优化首次可读内容的呈现。原路径要等 PDF.js 创建 worker、读取文件、解析并绘制页面，才有原文；渲染队列还会先请求当前页前面的邻页。

本机使用优化前代码、主线和安装版 Core 做了隔离对照，没有确认 0.4.12 相比 0.4.11 有稳定的首屏回退；这不代表首次打开的等待已经合格。本轮直接缩短首屏路径。

## 当前实现

- 进入 Reader 时先恢复目标页和阅读位置，保持该位置通过加载和窗口调整；从小节或学习记录进入时使用实际目标页，避免先闪现上次阅读页。
- 复用现有 Visual Region 的 PDFium 原页渲染：只请求当前目标页的完整原图，先显示真实原页。PDF.js 同时加载，绘制完成后替换预览，接上文字层、标记和学习交互。
- PDFium 在服务主线程导入时准备好；原页图片仍使用既有 PNG 规格与最多 4 条 / 8 MiB 的进程缓存，不新增磁盘图片、数据库表或依赖。
- 可见页按阅读焦点优先绘制，完成后再预读邻页；像素预算和最终清晰度保留。
- 当前页的 PDF canvas 完成后再开始习题、学习位置、AI 状态与正文准备请求，避免原页预览出现时这些请求仍与 PDF 解析争用资源。Practice 入口等收藏和继续位置加载好后再显示，避免加载期间展示错误的初始状态。
- 本机服务中的 32–256 MiB PDF 使用单条整文件流，避免 PDF.js 同时启动整文件流和分片读取。小文件保留原设置；大于 256 MiB 或大小信息缺失时保留 Range 能力，避免把较大文件的随机定位改成必须顺序读取。原 PDF、最终像素规格与坐标不变，不增加持久缓存。
- 预览核对 source SHA 与页码，并检查当前打开操作和 DOM 所属；退出或换书会取消请求。预览失败或来源不符时使用正常 PDF 路径。

## 实测

Windows，同一书库的只读 SQLite backup 和 PDF 副本，Edge 1440×1000、DPR 1.25，保留各书原来的阅读页与缩放。每本书使用新服务，再重开一次；没有清空操作系统文件缓存，不等同于重启 Windows 后的磁盘冷读。

| 真实样本 | 首次原页可见 | 同服务内重开 |
| --- | ---: | ---: |
| 组成原理，348 页书的 PDF 297 页 | 330ms | 79ms |
| 计算机网络，312 页书的 PDF 42 页 | 300ms | 55ms |
| 唐朔飞组成原理，436 页书的 PDF 16 页 | 431ms | 64ms |
| 数据结构，412 页书的 PDF 18 页 | 392ms | 58ms |

独立的最终防串页检查，组成原理 PDF 25 页约 281ms / 56ms。该组没有同时运行其他测试。此前四书采样期间有定向 Python 检查，以上数字按近似观察使用，不作精确百分比承诺。

安装版 Core 的精确对照样本中，网络书原路径首次完整原页约 894ms。最初预览版本的完整 PDF canvas 通常仍需约 0.7–0.9 秒；快的是原文先可读，不能把这称为全部交互在 55ms 内就绪。canvas 完成也不等同于选字可用，追加调查分别记录了文字层完成的时间。

首屏计时在真实绘制完成后打点，并检查图像像素，区分原页预览和最终 canvas。早期使用 DOM 轮询得到的约 0.85 / 1.35 秒有明显取样台阶，不据此认定回退或宣称提速。首次原页与最终 PDF 截图已目检，书页、位置和内容一致。

## 追加调查：首屏交互与浏览器对照

用户要求继续缩短可感知等待。使用相同书库副本、目标页和缩放，串行比较最初预览版本与后续加载调整；未清空系统文件缓存。以下为单轮观察，不能当成所有机器的稳定耗时或精确提速比例。

| 真实样本 | 调整前文字层就绪（首次 / 重开） | 调整后文字层就绪（首次 / 重开） |
| --- | ---: | ---: |
| 组成原理 PDF 297 页 | 1062 / 820ms | 498 / 413ms |
| 网络 PDF 42 页 | 973 / 830ms | 676 / 528ms |
| 数据结构 PDF 18 页 | 1217 / 950ms | 546 / 441ms |

上述三本约 124–145 MiB。后续使用最终产品代码再测组成原理，原页预览 249 / 70ms，canvas 488 / 450ms，文字层 490 / 468ms。最终检查同时验证了错误来源回退、加载中关闭、直接进入小节目标页，以及预览出现后先滚动，PDF 完成时不跳回原处。

分段观察显示，PDF.js 文档就绪约占数百毫秒。默认设置下本地整文件流与分片请求并存，首屏文字层出现前已接收接近整本书的数据；单纯让分片更小会增加来回请求，并未更快。64 KiB / 256 KiB 的纯按需方案、1 MiB 分片、从已知文件长度直接创建 Range transport，以及先单独绘制焦点页都做过局部对照，未作为产品实现保留。图片无损编码的差异只有几十毫秒，也未因此修改图像规格或压缩方式。

当前保留的改变是限制上述中等文件的重复读取，并延后后台学习请求。32 / 256 MiB 是保守使用边界，不是精确测出的最优阈值；超过此范围的文件没有据此宣称提速。唐朔飞书约 24 MiB，保留原加载设置，其复杂页和重开时间仍有波动。

浏览器原生对照尚未取得有效计时：Edge / Chrome 在本次自动化、实际窗口及独立测试配置中只显示了加载底色或 PDF 工具栏，没有成功显示目标书页。截图已检查，这些结果全部排除，不能据此称 Reader 比浏览器快，也不能把这一现象归因于用户日常浏览器。原生阅读器的实际差距仍待可正常显示书页的环境下复测；没有为了测量更改本地服务的来源校验或用户浏览器配置。

`tests-e2e/reader-first-open.mjs` 的 `READER_FIRST_INTERACTION=1` 追加文字层计时，`READER_FIRST_DEFAULT_LOADING=1` 可在测试页面保留默认 Range 路径。`READER_FIRST_NATIVE=1` 只采集原生窗口画面，必须核对真实目标页像素后才能得出计时；`READER_TEST_BROWSER` / `READER_FIRST_HEADED=1` 用于切换测试浏览器和实际窗口。实验性的分片和自定义 transport 参数已移除。

## 验证

- PDF 生命周期、坐标与可见页优先的 Node 检查共 29 项通过。
- Visual Region 定向 Python 检查 34 项通过。
- 真实浏览器验证：四本书首次打开 / 重开；来源错误回退；预览未返回时关书；从概览的小节入口直接进入正确页。
- 侧栏 11 项检查通过，覆盖选字解释、Master / Assistant / Guide 打开与拖拽、阅读位置和文字层对齐。
- 阅读显示 smoke 通过：保存标记翻页与重开、百分比编辑、Ctrl-wheel、Practice 命中和 Visual Region 坐标。
- 竖屏 smoke 通过：目录悬停与固定、右栏布局、切回横屏。
- Practice 离线 smoke 通过：三次 Hint、表格与跨页题、提交、Master Review、收藏记录返回和继续练习；新入口等待已保存状态加载完成。
- AI 使用本地替身或禁用，首屏路径 AI 调用为 0；未跑全量测试。

追加调整后重新通过：29 项 PDF 生命周期 / 几何检查、首屏来源 / 关闭 / 小节目标 / 加载中滚动检查、阅读显示与标记 smoke、Practice 离线 smoke（连续 Hint、跨页题、判题、Master Review、收藏记录返回与继续练习）。小文件唐朔飞样本保留原 Range 路径，正常打开与重开通过；大于 256 MiB 的真实文件本轮未覆盖，不宣称速度收益。

Practice 回归中复现了 Learning Memory 的既有分类切换时序问题：新分类请求未完成时，旧列表仍可点击，可能打开后又回到列表。已在共用分类切换处清除旧列表并收起旧内容，仍用现有“正在读取”状态，不改样式。测试持有分类请求，确认旧入口不可操作，释放后再找到收藏题并继续复盘；同时显式使用书内查找，不再假设打开书时恰好选中了目标习题所属小节。

## 范围与剩余限制

2026-10-23，用户已明确确认首屏与连续性能优化两组均人工验收通过，并授权在 main 单独收口、推送 GitHub。本次 checkpoint 同时收录两组实现、相关测试与报告；独立 OCR 加速实验和 website 不在提交范围。连续性能记录见 [READER_CONTINUOUS_PERFORMANCE.md](READER_CONTINUOUS_PERFORMANCE.md)。安装版 0.4.12 的文件未改动，Desktop 0.4.13 由桌面版对话另行从提交树集成，本对话不打包或发布。

预览清晰度受既有原图规格限制，随后完整 PDF 恢复原清晰度；选择文字等交互仍要等对应文字层。超复杂页面、尚未解锁的 PDF 或原页渲染不支持的文件会走正常 PDF 加载，不能承诺所有文件完全无等待。尚未做相同输入的浏览器原生 PDF 阅读器 / WebView2 精确比较。

后续 Desktop 集成要保留已有密码流程：该分支 `openBook` 的第二参数用于密码，本轮主线第二参数用于初始目标。应明确整合两个用途，保留密码取消、错误和解锁逻辑；不能直接覆盖该函数或 Desktop 的四角色模型与显示偏好代码。

测试工具为 `tests-e2e/reader-first-open.mjs`：`READER_DATA_DIR` 指定只读来源书库，`READER_FIRST_BOOK_PAGES` 选择书，`READER_FIRST_PRESERVE_POSITION=1` 保留当前阅读位置，`READER_FIRST_GUARDS=1` 检查回退和来源跳转。`READER_TEST_CORE` 可对照已有 Core；截图和计时保存在系统临时目录，结束后清理该次复制的数据。原教材、原数据库及凭据保持原样。
