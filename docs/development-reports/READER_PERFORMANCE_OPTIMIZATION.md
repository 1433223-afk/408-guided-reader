# Reader 通用性能优化

2026-10-22。接续 [性能调查](READER_PERFORMANCE_SURVEY.md)，处理已测出的共享瓶颈。已人工验收通过，本次收口主线 checkpoint，未打包或发布。原有 OCR 加速实验单独保留，默认仍为 CPU；本轮这些优化无需独立显卡。

## 做了什么

| 位置 | 修改 | 本机复查 |
| --- | --- | --- |
| PDF 开关 | 统一管理 PDF.js loading task；关闭、加载失败、快速切书和加载中退出均释放它，丢弃过期返回 | 五轮打开始终 1 个 worker，四次关闭均回到 0；原来会累积到 5 个 |
| 导入校验 | 用已有文件流校验并及时关闭 PdfReader；相同 SHA 的重复导入跳过解析 | 两份约 146 MiB 教材各导入两次，进程工作集约 117–118 MiB，没有因每次校验保留整份文件；重复导入没有执行校验器 |
| Practice | 复用已核验的 catalog 和题号到节的映射，查单题使用按节提取 | 重复 catalog 约 630–780ms → 17–18ms；收藏列表约 575–802ms → 20ms |
| 学习记录 | 批量读取小节状态与 thread；只复用显示位置，实时读取学习状态；当前章计数直接聚合 | entries 首次约 125ms，后续约 8.5ms；原来每次约 125–168ms |
| 搜索 | 一次搜索共用读取事务；复用字符归一化 | 常见词约 650ms → 162–184ms，连接约 102 → 2（含来源检查）；跨行、Unicode 和匹配位置规则不变 |
| 高倍缩放 | 邻页预绘制受 2400 万像素预算限制；所有可见页仍保留完整清晰度；释放离屏画布 backing store | DPR 1 / 400% 和 DPR 2 / 200% 均由约 360 MiB 降至 72 MiB 的 RGBA 尺寸容量 |
| PDF 裁图 | 同一来源与区域复用 PNG，最多 4 份 / 8 MiB；仍检查教材状态及文件变化 | 同区域重复裁图约 91–99ms → 2.7–3.5ms；首次含依赖加载约 212ms |
| Master 历史 | 消息内容不变时复用已排版 DOM，最多缓存 80 条，退出清空 | 原来 Master 打开 60ms、resize 52ms 长任务；本轮侧栏脚本 11 项均未记录到 50ms 以上长任务 |
| 后台任务 | 同一持久队列按原优先级取任务，将生成与审查交给单个后台线程；AI 忙时页面线程继续准备 OCR | 使用阻塞假 AI 实测章节生成、教学生成、教学审查三类；等待 AI 不再挡住新页面，同时优先的前置页面仍先完成 |

为了修复侧栏验证中真实暴露的工具栏溢出，准备状态和行间教学文字在空间不足时可收缩、省略；原来的按钮位置、更多菜单及缩放入口保留。

这些复用收益来自同一服务内重复访问。首次全书 Practice 提取仍约 0.8 秒；OCR / Outline 来源更新后也需要重建，不将重复访问的 17–18ms 当作冷启动成绩。

## 复用结果的边界

- SQLite 仍是唯一持久来源，没有新建缓存表或修改数据模型。派生结果每个 Database 实例最多保留 16 项。
- OCR、Outline、来源变化会失效相关结果；观察到其他连接写入时清空派生结果。收藏、作答和阅读位置等写入不会单独让教材几何重算。
- 返回派生数据的副本，调用方修改不会污染后续请求。已覆盖回滚、来源更新、删除书籍、外部连接写入和并发读写。
- 官方答案始终用于程序判题；公开题目与提交前 Hint context 仍排除答案、解析、correctness。没有为了提速改变对话、标记或学习状态的保存语义。
- 裁图缓存只复用原 PDF 像素；每次请求的 OCR、KP 和用户选择仍按现有路径组织。

## 没有采用的改动

PDF 分片做了真实页面对照：单纯从 64 KiB 增至 1 MiB，相关请求约 303 → 121，但该场景收到的数据约 170 MB → 275 MB。关闭流式整书读取、仅按需读取，在 64 KiB 下约收到 25 MB、工作集较低，但请求约 356，打开耗时约 1.86 秒，与对照约 1.79 秒没有明确速度优势；按需 256 KiB / 1 MiB 又会增加读取量。暂时保留产品默认值，实验参数只在调查脚本中生效。

这些网络数据取 CDP `dataReceived` 的累计接收量。`loadingFinished` 只统计完成的请求，不能把它的字节数当作所有 PDF 传输量。不同运行仍存在缓存与调度波动，不将单次结果推广到其他设备或远程部署。

没有做启动时自动压缩数据库，也没有改变静态资源和私人材料的缓存策略。实际 Provider 的首字延迟、低配电脑、官网网络、安装包冷启动仍未量化；不能用本地假回答宣称模型推理变快。

## 验证

- 定向 Python 检查通过：导入、搜索、派生缓存、学习与小节状态、Practice catalog / 作答 / Hint / Review / 多模态 / 收藏、Visual Region，以及后台 jobs / Knowledge / Teaching / Inline。后台阻塞测试另覆盖三类任务及前置页面优先的两种时序。未跑全量测试。
- Node 的 PDF session / geometry 共 28 项通过；改动的 JS / Python 语法检查通过。
- 真实 348 页组成原理 PDF：五轮开关、100% / 200% / 400% 缩放、滚动、DPR 2；没有页面错误，当前页保持原清晰度。画布容量是尺寸推算，不等于精确显存或进程独占内存。
- 侧栏性能脚本通过：Assistant、Master、Guide 开关与拖拽，阅读位置和文字层对齐保持；截图已目检。性能对照按串行执行，未把同时运行多个浏览器的采样用于最终结论。
- 真教材 Practice smoke 通过：表格跨页题连续 3 次 Hint、提交、Master 复盘，5.2.4 跨页题、退出后继续练习，收藏题从 Learning Memory 继续已有 Review。AI 为本地模拟回答，未出站；在实际调用边界核对题图 PNG，两页题图在 Hint / Review 中一致，提交前没有官方答案、解析和对错。
- 浏览器总工作集在反复操作中仍有增长，释放 worker 不等于浏览器所有分配立即归还；没有宣称解决了所有内存占用或排除了长期泄漏。

测量使用四书 1436 页书库的 SQLite backup 与 PDF 副本；原书库不写入。主要结果在系统临时目录 `reader-performance-optimized.json`、`reader-performance-survey-e6l0cooj`，侧栏及 Practice 验证日志也保留在系统临时目录。教材、数据库、截图和日志均未加入 Git。

调查脚本增加 `READER_PERF_RANGE_CHUNK` / `READER_PERF_DEMAND` 作对照；原先仅用于调查的 PDF destroy 注入已撤掉，当前直接测试产品释放逻辑。Practice 浏览器脚本可用 `PRACTICE_VISUAL_OFFLINE=1` 验证本地流程，不调用真实 Provider。
