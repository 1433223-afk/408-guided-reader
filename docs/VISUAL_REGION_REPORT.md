# Visual Region → Assistant prototype

更新：2026-10-03。状态：**人工验收通过**。用户已确认当前 Visual Region / 多模态区域解释及 UI 调整通过验收，创建独立 checkpoint。表格逐行解释的已知模型误读仍保留记录。

## 实现范围

- Reader 顶部现有工具栏增加小型“框选”入口。主动进入后在单页拖矩形，松手后可在框内拖动位置、从边缘或四角调整大小。淡绿选区、弱化角标，仅在选框附近显示“解释”和“×”；点击“解释”或按 Enter 确认后才裁图并打开现有 Assistant 草稿，同时清框并退出模式。Esc 取消且不打开 Assistant，快捷键不显示说明。
- 草稿可填写问题或直接发送。普通 Assistant 不重复展示裁图；展开后显示紧凑来源行，点击缩略图或“查看原图”才临时展示高清裁图。解释、流式输出、追问、选中回答再深入解释均复用现有 Assistant。
- 保存页面归一化坐标；坐标取 PDF canvas，不包含页脚或 Teaching 占位。后端从原始 PDF 渲染 PNG，216 DPI，长边最多 2048 px、总像素最多 3 MP。支持 PDF 旋转与 CropBox。
- 首问和后续问题直接携带图像。当前页/节、已有 KP 及最多 1600 字附近 OCR 仅作辅助；没有 OCR 也可用，不为框选启动 OCR。
- 使用现有 DeepSeek `deepseek-flash` / 智谱 `GLM-5.3-Flash`。不支持图像的配置会在出站前拒绝，不换 Provider。
- 图片仅存在于临时解释内存及浏览器预览，不写数据库、截图历史或请求检查器。关闭主题释放预览。第一版不把图片解释保存成文字选区笔记。

## 相关保护

区域模式只拦截主动进入后的拖动；Esc、右键、失焦、拖动中布局变化会取消。页面虚拟化移除原 canvas 时取消本次框选。普通阅读、文字选择及 Practice 键盘入口保持原路径。

PDFium 裁图与原有 OCR 渲染共用锁。服务端重新从书库 PDF 生成送出的图像，不信任客户端传入的图片或 OCR。首问期间切换解释主题时，预览绑定新创建的视觉主题，不绑定可能已切走的焦点。
